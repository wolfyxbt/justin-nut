# 开发说明

## 结构

| 路径 | 用途 |
| --- | --- |
| `index.html` | 页面、植物卡片、游戏菜单、YouTube 视频面板 |
| `style.css` | 桌面 / 手机布局、视频面板排版、开场植物卡片 |
| `plants.js` | 植物数值、角色状态、待机动作参数 |
| `assets/chapters.js` | 视频章节的时间点与标题，页面据此生成章节按钮 |
| `game.js` | 无尽保龄球的游戏循环、输入、实体、碰撞、绘制与音效 |
| `assets/` | 可运行资源、动画图集与素材来源清单；`dialog-frame.png` / `button*.png` 是原版九宫格与三段按钮拼成的整图，供 CSS `border-image` 使用 |
| `scripts/serve.mjs` | 无外部依赖的静态服务器 |
| `scripts/build-offline.py` | 单文件 HTML 导出 |
| `scripts/test-engine.mjs` | 游戏逻辑、鼠标和触屏输入的回归验证 |
| `scripts/check-public.mjs` | 公开文件、凭证模式、内部文案和文档链接检查 |
| `.github/workflows/verify.yml` | GitHub Actions 验证 |

游戏逻辑使用 900 × 600 坐标，草坪为五行九列，只运行无尽保龄球。滚动速度、补给间隔、传送带容量、传送带滑动速度、各类植物概率、红线列数都在 `game.js` 顶部的 `bowl` 对象中。爆炸半径在 `plants.js` 的 `boomnut.blastRadius` 中，两种向日葵的生命值、产出类型与间隔分别在 `nutflower` 和 `zengflower` 中，出怪节奏在 `updateBowling` 中。

传送带是 DOM 元素，底板与皮带是原版图片（皮带 6 帧用 CSS 步进动画循环），每张卡片一个按钮，由 `updateBelt` 按 50 像素槽位定位。`state.plants` 保存种下的两种向日葵，`state.rolling` 保存滚动的坚果，`state.drops` 保存花朵产出的地上坚果，`state.heldNut` 保存当前拿起的一颗坚果。地上、手持和滚动坚果都保留 `type`。拿起后必须先放到有效格子，才能继续取卡或使用铲子。

开场「准备 / 开始 / 种植物」用原版文字图在画布上绘制。手机界面将工具栏独立放在草坪上方，并裁去画布顶部的装饰区，输入会映射回原始坐标。游戏加载器只加载当前玩法实际使用的角色动画。

## 验证与离线导出

需要 Node.js 24 或更新版本。单文件导出还需要 Python 3.10 或更新版本，使用 Python 标准库，无需额外安装库。

```sh
npm ci
npm run verify
npm run build:offline
npm run verify:offline
```

`npm ci` 安装的开发依赖仅用于测试，不会加载到游戏页面中。GitHub Actions 会在推送和提交 Pull Request 时执行上述验证。

提交前可单独运行 `npm run audit:public`，检查常见的个人文件路径、凭证模式、内部文案与失效的本地文档链接。该检查也包含在 `npm run verify` 中；它不能识别所有形式的敏感信息，提交前仍需检查实际改动。

单文件版本保存在 `dist/justin-nut.html`，内含脚本、样式、图片和音频，游戏部分可以离线打开；嵌入的 YouTube 视频仍需联网。`dist/` 默认不提交到 Git。

## 发布目录

运行 `npm run export:public`，会在 `dist/public/` 下生成独立的发布目录，只包含运行资源、源码、测试、文档与许可文件。该目录不包含版本历史。修改项目后应重新导出并验证。

## 测试范围

`npm run verify` 包括 JavaScript 语法检查、公开文件审计和保龄球验证。覆盖单一开始入口、倒计时、暂停与重开、失败结算、最佳成绩、鼠标携带、传送带补给与取卡、红线限制、弹跳、计分、爆炸坚果、割草机，以及两种向日葵的产出与啃咬。

触屏检查覆盖 316 / 370 / 460 像素宽度的点选、拖动、无效落点、手势取消与铲除。两种产出的坚果均覆盖空与满传送带、必须先放下的手持状态、暂停和重开时的行为；曾颖向日葵还覆盖未喂食不生产、每颗输入只转化一次、10 秒等待、拒绝重复或红色喂食、准确扣除选中卡片、收获坚果喂食、触屏取消和拖动、暂停及移除后的转化状态，以及红色产出投放后的范围爆炸。动画检查确认两种向日葵的帧时长、轮廓、绿色茎叶保留原素材，景甜花瓣保持原色、曾颖花瓣呈红色，并检查播放、暂停和继续。曾颖的普通与发光图集还通过实际纹理逐帧对齐检查，确保脸部大小固定、状态切换不跳变。还验证后台模拟继续运行、音量范围和播客章节跳转。

测试还会在实际曾颖向日葵图集中，沿每帧花盘两侧检查原贴图边界内外的平均颜色，防止携带静态外沿或异色扩展纹理而产生第二圈光晕。

喂食提示检查覆盖鼠标与手机空手点击、提示自动消失、取消轻点不误触、待喂食和转化时均无常驻文字。错误喂食覆盖红色坚果及两种向日葵，验证只播放一次 `error` 提示音、不扣卡片、不弹文字，并遵循静音和游戏音量。错误音为本项目合成的短双音，文件为 `assets/error.mp3`，离线构建沿用现有音效内嵌流程。

生成动画检查实际绘制的红色果实：未喂食时不出现，喂食后立即出现并持续长大；成熟前不能拾取。验证暂停时的果实像素不变、多株独立进度、成熟后位置与大小连续转为唯一掉落物，以及拿走成熟果实后另一株继续生长。生成过程不增加文字或进度条。

测试执行实际 `game.js` 与 Canvas 绘图，但 DOM 和时间由测试环境模拟。测试不替代浏览器排版、音频播放、真实手机手势与性能验证。`npm run verify:offline` 在单文件版本上执行同一套检查。

乒乓球僵尸的检查覆盖自然出怪、速度、专属跑动与啃咬图集、暂停时停帧、三次普通撞击的生命变化、计分、对应头部脱落、倒下，以及爆炸坚果和割草机击倒。掉落头部还验证暂停停位、落在草地上与停留后消失。

手动检查：开场卡片、草坪携带和落点、暂停后继续、音量开关与游戏音量、重新开始、切到其他窗口后游戏继续推进、横竖屏切换与不同窗口大小。

游戏地址加 `?debug=1` 会启用 `window.pvzDebug`，用于本地调试和自动测试。普通游戏不会启用此接口。该接口只操作浏览器内的游戏状态，没有服务器或账户数据。
